# Выбор доступного пути

Не требуйте конкретный сервис. Проверяйте, что инструмент действительно доступен и операция проходит: имя в конфигурации или успешный `--help` не доказывают просмотр экрана.

| Задача | Предпочтительный доступный путь | Без него |
|---|---|---|
| Найти рабочие экраны | Подключённая библиотека экранов, реальные демо продуктов | Поиск по публичным сайтам, авторским портфолио, справке продукта |
| Найти визуальное направление | Pinterest, X, Dribbble, Behance, галереи | Скриншоты пользователя, собственные оригинальные исследования |
| Просмотреть изображение | Разрешённый просмотрщик/браузер достаточного разрешения | Попросить доступный кадр; не приписывать просмотр ссылке |
| Найти компоненты | Уже установленный UI-kit, официальный registry/API | Native семантические контролы или совместимая библиотека проекта |
| Figma | Подключённый инструмент с реальным file/node ID | Экспорт пользователя или локальная реализация; не выдумывать подключение |
| Рендер | Браузер проекта/доступный инструмент снимков | Опциональный `render_web.py` для локальной статической сборки |
| Сохранить паттерны | Markdown/JSON в рабочем проекте | Детерминированный поиск `pattern_catalog.py`; внешняя БД не нужна |

Подключение нового MCP, установка зависимостей, публикация или изменение настроек — отдельные действия в рамках авторизации проекта. Навык сам их не выполняет. Если сервис требует входа, пользователь входит сам; пароли и session cookies не нужны в каталоге.

При отсутствии всех визуальных инструментов можно подготовить UX, структуру, промпт и исходники. Указать `visual: not-run`, а не объявлять результат визуально проверенным.

Схемы receipt и `tool_receipt.py` проверяют переданные квитанции. Они не подключают сервис и не превращают синтетический тест в реальный вызов MCP.
