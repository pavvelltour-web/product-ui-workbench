# Реализация и библиотеки компонентов

Сначала посмотрите существующий проект: package manifest, версии, реальные импорты, темы, стили, поведение контролов. Не добавляйте второй UI-стек без причины.

| Есть в окружении | Рабочий путь |
|---|---|
| Готовые компоненты проекта | Использовать их API и семантику, изменить композицию и токены |
| React + shadcn/Radix | Официальные исходники/registry или сохранённые MIT-снимки из `library/components/react-shadcn` |
| Другой UI-стек | Найти совместимые компоненты в его официальной документации |
| Нет Node и UI-библиотеки | Native HTML/CSS/JS, семантические формы и контролы; см. `examples/offline-demo` |
| Только дизайн без кода | Макет/спецификация с честным `browser: not-run` |

Папка сохранённых React-компонентов не устанавливает их зависимости. Прочитайте её API, dependencies и лицензию. Для новых зависимостей следуйте авторизации проекта; не выполняйте глобальные установки как скрытый шаг навыка. Официальная инструкция: [shadcn/ui installation](https://ui.shadcn.com/docs/installation).

Чтобы назвать реализацию библиотечной, нужны реальные импорты, совместимые версии/API, сборка и проверенные состояния. Название `Button` у собственного div не доказывает использование shadcn.

Проверяйте вместе с хостом: controlled/uncontrolled value, выбранное значение Select, фокус после закрытия, Escape, портал поверх стекла, pending/disabled/error, сохранение черновика и конкретного ID. Ни один источник компонентов не делает эти проверки за приложение.

Библиотека даёт поведение, доступность и повторяемость. Выразительность создают иерархия, пропорции, типографика, цветовые роли и разные компоненты для разных задач.
